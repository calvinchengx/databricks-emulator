# v0.2.2

**Unmodified `dbt-databricks` against a Unity Catalog catalog.** Warehouse
`CREATE TABLE cat.sch.t` with no `LOCATION` is the managed shape a real
workspace accepts and UC OSS plus Sail do not. This release rewrites that
statement on the warehouse path so the files land and the name still
resolves. Contoso gold no longer needs adapter stubs.

```
docker pull ghcr.io/calvinchengx/databricks-emulator:0.2.2
```

## Managed CREATE, as an EXTERNAL write

UC OSS has no managed handshake Sail speaks (`io.unitycatalog.tableId`). A
three-part `CREATE TABLE` with no `LOCATION` now:

1. Allocates `file:///data/delta/managed/cat/sch/t` (`DATABRICKS_DELTA_ROOT`
   overrides the prefix).
2. Sends Sail an unqualified `CREATE TABLE IF NOT EXISTS \`t\` … LOCATION`.
   `CREATE OR REPLACE` is stripped — UC OSS rejects it.
3. Registers an EXTERNAL table in UC OSS. `DESCRIBE` uses the same Spark
   session as the write (Sail's memory catalog is session-scoped) and
   accepts array-shaped DESCRIBE JSON, not only object rows.

`INSERT` / `SELECT` keep the three-part name. `hive_metastore` and
statements that already have `LOCATION` are left alone.

Spark SQL `information_schema.*` (`tables`, `row_filters`, …) succeeds with
an empty schema envelope so Sail is not asked for a catalog it does not
serve. A HiveServer2 result with no columns now carries an empty `Columns`
list; a nil list crashed `databricks-sql-connector` on `CREATE SCHEMA`.

`CREATE SCHEMA cat.sch` goes to UC REST; 409 / already-exists is success.

## Witness

`make e2e-dbt-uc` — unmodified `dbt-databricks==1.12.4`, `catalog` set, no
post-hook. **delta-rs** reads `managed/e2e/gold/{one,two}`; a three-part
warehouse `SELECT` confirms the same rows. `make e2e-dbt` remains
hive_metastore Thrift smoke. `make e2e-delta` also creates
`e2e.s.from_shim` with no `LOCATION`.

Jobs `dbt_task` stays refused.

## Upgrading

Pull `0.2.2`. Consumers that pointed dbt at a UC catalog and papered over
`CREATE OR REPLACE`, `information_schema.row_filters`, or a UC storage root
can drop those workarounds. Keep a scheme-free host and `_connection_uri`
if the connector would otherwise force `https://`.
